02 / Event cycle
Decision-time ordering

Trade after public action. Reveal after settlement.

The sequence is part of the model. A valuation may use the frozen public state and future-policy branches, but never the private card, future random draw or terminal result that the trade precedes.

  1. 01

    Load configuration

    Fix games, contracts, fees, limits and the run seed.

  2. 02

    Initialize games

    Create up to twenty independent Kuhn or Leduc underlyings.

  3. 03

    Advance public action

    Apply the latest legal game action under the configured policy.

  4. 04

    Freeze public snapshot

    Expose only the state available to market participants.

  5. 05

    Enumerate local futures

    Expand hidden deals and equilibrium-policy action branches.

  6. 06

    Merge payoff states

    Aggregate terminal histories with the same registered payoff vector.

  7. 07

    Assign scenario weights

    Keep benchmark, maker and user measures explicitly separate.

  8. 08

    Mark contract values

    Map each measure through the same payoff registry.

  9. 09

    Reserve and skew

    Translate inventory covariance and uncertainty into quote centers.

  10. 10

    Publish 20 × 2 depth

    Construct bid and ask ladders before the next underlying action.

  11. 11

    Evaluate combined book

    Score candidate packages with old positions, costs and tail limits.

  12. 12

    Atomic pro-rata fill

    Use one immutable book and one common fill ratio for every leg.

  13. 13

    Reveal, settle, log

    Only now expose the terminal state, transfer payoff and close invariants.

03 / Information model
One payoff basis · three measures

Separate what happens, what pays and what each agent believes.

The system keeps terminal generation, contract payoff and scenario weighting as independent layers. The true benchmark is evaluation-only and cannot be used by either trading agent.

Public observation

Finite game snapshot

Pot, action history, legal moves and registered contracts define the observation available to the market.

  • Kuhn for exact small-tree checks
  • Leduc for public-card and checkpoint structure
  • Trade before the next underlying action
Engine-private

Hidden state stays hidden

Private cards, seed, future actions and the realized terminal state remain behind the engine boundary.

  • No look-ahead valuation
  • No benchmark leakage
  • Reveal only after decision
Registered payoff

Contracts are functions

Futures, options and swaps map the same terminal history to different cash flows before positions are valued.

  • Winner-linked binaries
  • Strike-dependent options
  • Path-dependent variance exposure
04 / Market mechanics
Scenario → quote → risk → fill

The decision object is the combined portfolio.

A fair value is not a fill price. Spread, depth, inventory covariance, transaction cost and the old portfolio all remain inside the package decision.

06 / Engine roadmap
Not implemented in this portfolio revision

Make the private engine emit public evidence, not private state.

When the original repository is available, the interface can replace reconstructed rows with a sanitized, hashed artifact without changing the page’s decision contract.

Roadmap / 01

Typed state boundary

Separate immutable PublicSnapshot from engine-private cards, seed and future actions at the type level.

Roadmap / 02

Versioned payoff registry

Bind contract definitions and the terminal payoff matrix to an explicit schema and content hash.

Roadmap / 03

Exact / Monte Carlo split

Retain exact single-game oracles while sampling only the joint multi-game portfolio distribution.

Roadmap / 04

Solver evidence

Record feasibility, CVaR auxiliary variables, tolerances and termination status for every proposed package.

Roadmap / 05

Two-phase package commit

Add prepare, common-fill, commit and rollback records with cash, position and depth invariants.

Roadmap / 06

Evidence artifact

Generate eventedge-evidence.v1.json with seed, config, commit, scenario and result fingerprints for later portfolio synchronization.

Roadmap / 07

Validation campaign

Cross-check Kuhn exact probabilities, CFR diagnostics, property-based accounting, net-cost OOS episodes and dependent-tail uncertainty.
