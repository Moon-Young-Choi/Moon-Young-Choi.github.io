01 / Request flow

One request · one frozen context

Access → As-of → Calibration → Forecast → COSMOS → Portfolio

The ordering is a contract: calibration completes before the current pair is combined, and only the final portfolio may cross the response boundary.

  1. 01AccessPortfolio Experience

    A protected entry boundary accepts the asset universe, objective, and a supported forecast horizon.

  2. 02As-of resolutionData & Evidence

    One latest-complete cutoff is resolved against the separate observation requirements of both algorithms.

  3. 03CalibrationAlgorithm Weight Calibration

    Historical A/B forecasts and result-window prices are prepared through independent branches; only complete pairs with mature labels enter the request-specific sample.

  4. 04ForecastAlgorithm Services

    Independent A and B services receive separate point-in-time bundles under one fixed Forecast Context.

  5. 05COSMOSDecision & Portfolio

    The complete current A/B pair and request-specific weights are combined into a joint distribution.

  6. 06PortfolioDecision & Portfolio

    The optimizer receives the joint distribution and request constraints; only the final portfolio crosses the response boundary.

02 / Architecture

Navigation boundaries · not deployment units

Five operational domains

The domain map shows ownership and forbidden crossings. Concrete cloud products remain intentionally undecided.

01

Portfolio Experience

Own the protected request and final-response boundary without persisting a portfolio request.

  • Web appPortfolio Console

    Collect the asset scope, objective, and common supported horizon; display only the final portfolio.

  • API servicePortfolio Request API

    Validate the compatibility manifest, pin the Forecast Context, and return only the final result.

02

Data & Evidence

Assemble algorithm-specific point-in-time evidence and provide normalized price series through one internally owned source path.

  • ServiceEvidence Assembly Service

    Resolve readiness, plan source access, and assemble separate A/B bundles at one compatible cutoff.

  • ServiceMarket Price Service

    Own the FSC price path; normalize price series and report interval coverage or readiness without calculating returns.

  • JobDART Source Connector

    Collect, parse, clean, and split disclosure responses only when requested by Evidence Assembly.

  • JobFSC Stock Price Connector

    Collect FSC daily-price responses only when invoked by Market Price Service; do not calculate returns.

  • ServiceExact Data Plane Service

    Prepare structured disclosure data as Exact Evidence without normalizing prices or calculating returns.

  • ServiceShared Evidence Encoder Service

    Run only the common source encoder and produce Shared Latent Evidence; algorithm-specific decoding stays inside A/B.

  • Ephemeral resourceRequest-Scoped Data Workspace

    Reuse compatible source responses, normalized prices, shared encoder outputs, and in-progress evidence within one request only.

03

Algorithm Services

Execute purpose-independent A/B forecasts under the same immutable Forecast Context.

  • ServiceConclusion Request Gateway

    Accept current or historical contexts and return a complete A/B pair or an explicit failure.

  • ServiceAlgorithm Evidence Coordinator

    Query separate requirements, coordinate the common cutoff, and deliver each bundle to its owning algorithm.

  • Plugin boundaryAlgorithm A Service

    Own A observation requirements and map its fixed context plus evidence bundle to Conclusion A.

    Logical childEmbedded Decoder A
    Interpret Shared Latent and Exact Evidence inside the pinned Algorithm A service version.
    Logical childForecast Function A
    Produce Conclusion A for the requested As-of and horizon without reading the portfolio objective.
  • Plugin boundaryAlgorithm B Service

    Own B observation requirements and map its fixed context plus evidence bundle to Conclusion B.

    Logical childEmbedded Decoder B
    Interpret Shared Latent and Exact Evidence inside the pinned Algorithm B service version.
    Logical childForecast Function B
    Produce Conclusion B for the requested As-of and horizon without reading the portfolio objective.
04

Algorithm Weight Calibration

Re-estimate A/B weights for each portfolio request from complete historical samples under pinned versions.

  • JobCalibration Runner

    Replay historical contexts and admit only complete A/B pairs whose outcome interval has matured.

  • JobHistorical Return Evaluator

    Request normalized historical prices only through Market Price Service and return a mature realized return or an invalid sample.

  • JobWeight Optimizer

    Score candidate weights against complete samples for the current asset scope and horizon.

05

Decision & Portfolio

Coordinate context resolution, calibration, the current forecast, distribution combination, and final optimization.

  • ServiceDecision Request Coordinator

    Provide the single entry and exit for the decision boundary; direct access to source data is forbidden.

  • ServiceCOSMOS Distribution Service

    Combine time- and version-compatible A/B conclusions with request-specific weights.

  • ServicePortfolio Optimization Service

    Calculate the final portfolio from the joint distribution and request objective or constraints.

01

Immutable Forecast Context

Asset universe, forecast horizon, resolved common As-of, and compatibility-manifest versions are pinned before calibration or current inference.

02

Separate A/B evidence

Observation requirements and bundle requests are never merged; each algorithm receives only its own evidence contract.

03

Complete pair or fail

Every current or historical As-of returns both conclusions or a failure; partial pairs never enter COSMOS or calibration.

04

One price path

Market Price Service is the sole internal owner of FSC price access; Historical Return Evaluator obtains normalized historical prices only through that service.

05

Mature labels only

A historical sample is eligible only after the full outcome interval has ended and the realized return is available.

06

Anti-lookahead reuse

A response prepared at a later cutoff cannot satisfy an earlier As-of, even inside the same request.

07

Request-scoped cleanup

Temporary responses, evidence, and returns are removed on request completion, failure, or timeout and are not reused across requests.

06 / Failure & boundary

Fail closed · claim narrowly

What stops the request

A failed prerequisite is visible as failure. The architecture does not substitute a stale, partial, or simulated portfolio result.

  1. 01

    No common latest-complete As-of satisfies both independent observation contracts.

  2. 02

    Either current Algorithm A or Algorithm B conclusion is missing or incompatible.

  3. 03

    The calibration window contains fewer than the configured minimum complete, mature samples.

  4. 04

    The requested horizon is absent from the pinned compatibility manifest.

  5. 05

    Historical price coverage is incomplete or the result window is not mature for enough calibration samples.

  6. 06

    A source response, normalized price series, evidence bundle, return, or conclusion crosses its permitted time or request boundary.

  7. 07

    The optimizer cannot produce a result that satisfies the request constraints.
